## 候选一:标注 walk 并入共享 seam(triage 核实:坐实)

「段落→splitSentences 分句→逐句 buildIpaSlots 槽位;image 占位;code/raw 直通」
的 dispatch 在两宿各一份:

- server `buildChapterBlocks`(apps/server/src/import/pipeline.ts)→ 产出
  `BlockRow`(SQLite 写形状,含 ipaText=slots.join(" ").trim() 与
  translation:null 派生列)

  `ExtBlock`(仅 ipaSlots,无派生列)

`IpaLookup = (token) => string | null` 即共享 seam,server 已有
`ipaLookupOf(dictionary)` 适配先例(dict/ipa-line.ts)。分句规则/占位纪律/
词-音标配对遍历是扩展 spec 承诺「两端一致、唯一真相源」的载体,任何规则变更
今天都要两处同步——这是本票的实质风险,不只是审美。

PDF 不在此列:pdf.ts 走原位叠加管线,不产 ExtBook,只共享 IpaLookup/WORD_PATTERN。

## 候选二:chrome 后端 namespace 读写助手(triage 核实:坐实,且写纪律分叉)

与票 07 vocabulary 互吞 bug 同类。

## Agent Brief

**Category:** enhancement
**Summary:** 标注 dispatch 收敛进 @lingualeaf/import-core 两宿一份;extension
chrome 后端 namespace 读写样板收进带写队列的小助手,vocabulary/library 统一串行写。

**Current behavior:**
两宿各自实现 chapter.items 的 kind 分派(段落分句+槽位、image 占位、code/raw
直通);server 侧附加 ipaText/translation 派生列。两个 chrome 后端各有
namespace 读改写样板,vocabulary 有写队列、library 无(注释以「单写者」为由,
该前提与防抖自动存 + 切文档场景相抵)。

**Desired behavior:**
dispatch 唯一实现在 import-core,宿主经回调产出各自形状(先例:buildIpaSlots
的 IpaLookup 参数形状);两宿行为零变化。extension 一个小助手封装 namespace
记录的读(带默认)与写,写路径统一走队列互斥,两后端共用;library 旧注释按
「写经单队列串行」改写。

**Key interfaces:**
- `IpaLookup = (token) => string | null`(import-core 已有);server 的
  `ipaLookupOf(dictionary)` 适配已存在,`buildChapterBlocks(book, dictionary)`
  对外签名不变。
- 共享 walk 建议形状(签名实现定):chapter 级泛型 `walkChapterBlocks<T>(

  级返回 T[][]——契约是分句/配对/占位 dispatch 唯一,宿主映射各自保留

- namespace 助手建议形状(签名实现定):`createNamespaceRecord<T>(namespace,
  empty)` → `{ read(): Promise<T>; write(mutate: (record: T) => T | void):
  Promise<void> }`,write 内部入队(票 07 enqueue 先例);**读不排队**。
- 等价钉:import-core testing/ 的 epub fixture 可直接驱动两宿输出等价断言。
