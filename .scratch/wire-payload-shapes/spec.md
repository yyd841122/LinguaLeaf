## 问题

wire.ts 的类型级单源只覆盖枚举 + `ChapterTranslationState`;阅读对/书架行的载荷形状
四处手抄:web `ReadingView.tsx` 的 SentenceBlock/PassthroughBlock/ImageBlock/Block/
ChapterContent、`ReadingPage.tsx` 的 ChapterContent 拼接 + TableOfContents、
`BookshelfPage.tsx` 的 BookSummary。server 侧 shape 源在 `book-store.ts`
(SentenceBlockData/PlainBlockData/ChapterData),router 在 `books-router.ts` 的
toChapterPayload 拼 wordStatuses + translationAvailable。改形状时两 tier tsc 全绿,
只有 contract 套件(runtime)能红——恰是 wire.ts 头注释宣称要消灭的失效模式。

## 决策(六条,grilling 已锁)

1. **家**:wire.ts 原地扩展;web 继续 type-only 相对导入(6 个既有调用点模式不变)。
   不进 reading-model(charter 是领域模型),不建新包(YAGNI)。
2. **范围**:wire 导出 `SentenceBlockPayload` / `PlainBlockPayload` / `BlockPayload`
   联合 / `ChapterPayload` / `BookSummary` / `BookToc` 六个名字,对应删除 web 四处
   活体手抄。
3. **测试面**:contract 套件既有 runtime pin 原样保留;新增对齐钉——每个 sentence
   block 断言 `wordStatuses.length === segmentOriginal(originalText)` 词数(两端共用
   reading-model 分词,位置对齐从注释承诺变接缝断言)。
4. **命名**:Payload 后缀家族;store 解码形状名(SentenceBlockData 等)不动、不导出;
   web 允许 ReadingView 一行 re-export 旧名(Block 等)少动调用点。
5. **记档**:wire.ts 头注释 charter 改写(枚举 + 四元组 + 阅读对/书架行载荷);改口
   理由落本票 Comments;不立 ADR(类型布局可逆)。
6. **载体**:本票经 /implement 实施,过双轴 review。
