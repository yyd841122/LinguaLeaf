# 08: 容错与导入进度反馈

**What to build:** 导入过程可见、失败不吓人：导入时能以阶段或百分比看到进度，完成后书架状态更新；音标缺失与译文失败的句子按容错规则展示（该行留空或只显示可用行）；文件损坏等导入失败有明确提示且不留半成品书。

**Blocked by:** 03 ECDICT 音标行 + 查词 API；04 DeepSeek 译文行；07 EPUB 导入

**Status:** ready-for-human

- [x] 导入进行中可见进度（阶段或百分比），完成后书架状态更新为可读
- [x] 音标查不到的词留空、译文失败的句子只显示可用行，阅读不被破坏
- [x] 导入失败（损坏文件等）给出明确错误，不产生残缺的书
- [x] API 缝测试：坏文件导入失败路径、假翻译器部分失败路径

## Comments

- 2026-10-17 (Claude): 票 04 评审转记:导入目前是单个同步 POST,翻译按批串行(roundtrip 最长 120s/批)——长书整本翻译可能把单请求拖进小时级,超出 ADR 0002"导入等几分钟"的成本包络,客户端/代理会超时。本票做进度反馈时应把导入改为异步任务(书架状态流转),顺带化解该风险。

- 2026-10-18 (Claude): 实现。**导入改异步任务**（采纳 2026-10-17 评审意见，化解整本翻译拖垮单请求的风险）：POST 同步完成格式解析（坏文件仍同步 400/415，零落库），随后建 books 行（status='importing'）即回 **202**，标注任务后台执行——books 表新增 status/import_stage/import_percent/import_error 四列（旧库原地 ALTER 迁移，旧行默认 ready；schema.test 固定）。任务三阶段：annotating（分句+IPA，快）→ translating（每批回写百分比）→ saving（单事务插入章节+块并翻转 ready）。**百分比语义**：按已处理句位计数、显示封顶 99%（重试轮会把计数推满，100% 留给真正完成；code-review 后修正）。**失败路径**：任务内部故障 → status='failed' + 书架明示「导入过程中出错，请重试」（原因进服务端日志）；启动清扫 failInterruptedImports 把重启遗留的 importing 行标为「服务重启，导入中断」；INSERT 全在单事务，失败/中断零残留（failed-import 缝测试断言 chapters/blocks 计数为 0）。**阅读保护**：未 ready 的书，章节/进度路由一律 409「book is not ready for reading」，删除随时可用（删除中导入 → 任务续跑检测到书已删、静默放弃，缝测试断言无僵尸行）。**前端书架**：有导入中书时 1.5s 轮询书架列表；行内按状态渲染——导入中显示「导入中 · 翻译译文 40%」等阶段文案（未知阶段回退「处理中」，不裸出英文枚举）、失败显示原因、仅 ready 出阅读链接；翻译/查不到的音标按 03/04 容错规则照旧（NULL 行留空）。**测试**：API 缝 5 组新增/改造（held 翻译器钉住导入中 translating 0%、生命周期守卫 409、删除中导入、注入词库故障的 failed 全路径、坏文件 400/415 后书架零行）+ 假翻译器部分失败（ready 且 NULL 落库）+ 迁移 2 + 启动清扫 1 + 批次进度回调 1 + 书架组件 4（导入中→ready 转换、停轮询、阶段文案、失败行）。**门禁**（退出码已验）：typecheck、115/115、lint、build（npm run verify）；生产 E2E 两轮（--noproxy）：无翻译器 202→ready→IPA 实词库→坏 epub 400→非书 415→删书 204 全链；真 DeepSeek 30 句书 POST 即回 translating 0% → 轮询见 67% → ready，译文逐句落库。**code-review 双轴**后修复：① 重试期间百分比显示 100% → 封顶 99；② 未知阶段裸英文 → 「处理中」回退 + 文案覆盖测试；③ status 三态改联合类型（路由/前端）让编译器盯三分支；④ settled UPDATE 形状收敛为一处；⑤ 译文缝测试统一走共享 helper。复核后不改：任务内故障书架文案保持通用（具体原因在日志，UI 文案稳定）；409 守卫/启动清扫/迁移/轮询是异步化的直接后果而非加戏；import 四列保持平铺（贴表结构）；IPA 前半同步执行（快，代码有注）。**人工验收提示**：任一 EPUB/MD 上传后书架立即出现「导入中 · …」并每 1.5s 刷新，完成后变可读链接；导入中途刷新页面、或重启服务，分别验证进度恢复与「服务重启，导入中断」。

- 2026-10-18 (Claude): 验收反馈修复（bf67d9b）：翻译进行中「导入」按钮保持禁用（显示「导入中…」）直到书架无导入中书——202 秒回后按钮原本立刻恢复可点，可重复提交；组件测试补一条（导入中禁用→ready 恢复）。门禁：verify 116/116。

- 2026-10-18 (Claude): 验收反馈修复 2（见 fix commit）：验收发现「导入中杀服务后页面无任何提示」——排查：服务端重启清扫链路正常（生产构建 + 真实浏览器 Playwright 全流程复现，重启后 ~1.5s 行内出现「服务重启，导入中断」）；真正缺口是**页面开着、服务没起来**时轮询静默失败，旧页面永远停在「导入中 0%」。修复：轮询失败且仍有导入中书时显示「无法连接服务端，导入进度可能已过期」警告，恢复后自动消失。另确认用户当时服务实际未启动（:3000 无监听，书 16 挂在 importing）——重启后清扫会把它标为失败提示。门禁：verify 117/117。
