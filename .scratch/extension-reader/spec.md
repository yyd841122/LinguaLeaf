# Spec: extension-reader — 浏览器扩展（无服务本地标音）

Status: ready-for-agent

依据：ADR-0006（彻底无服务本地标注）、ADR-0005（四态词元状态）、GLOSSARY.md（音标行、标注、书、生词本、词元、浏览器扩展、扩展阅读页、离线词典、属主令牌）。Codex 独立评审（read-only，verdict NEEDS REVISION，单轮已封）的补齐项已全部折入。

## Problem Statement

我在浏览器里读英文书时想随手看到音标，但每次都得先把 LinguaLeaf 的 Node 服务手动跑起来——忘了起服务、起错端口、占着 3000 的旧实例，任何一步都打断阅读。我想要的是：打开 PDF/EPUB 这个动作本身就能见到音标，全程不存在「启动服务」这件事——不手动起，也不要后台常驻或自动拉起。

## Solution

一个 Edge 浏览器扩展：自带扩展阅读页，把 EPUB/PDF 文件交给它打开，音标行由随扩展分发的离线词典在浏览器本地生成——无网络、无服务进程、无 API key。点词弹卡看词元、美音 IPA、词性、中译并管理生词本四态；阅读进度被记住，下次接着读。生词数据先由扩展自管，与词架的同源合并留作后续独立决策（ADR-0006）。

## User Stories

1. 作为英文学习者，我想要点击扩展图标后选择或拖入一个 EPUB 文件，以便无需任何服务启动动作就进入带标注的阅读。
2. 作为英文学习者，我想要每个词的正下方成对显示美式 IPA 音标行、随原文换行逐词对齐，以便阅读视线不离开原文就能顺带认音。
3. 作为英文学习者，我想要一键显示/隐藏音标行，以便干净阅读和注音阅读随时切换。
4. 作为英文学习者，我想要词典查不到的词在音标行留出空槽而不是报错或挤乱排版，以便生僻词不破坏整行对齐。
5. 作为英文学习者，我想要点词弹出详情卡（词元、美音 IPA、词性、中译），以便停下时弄清这个词。
6. 作为英文学习者，我想要词形查不到音标而回退到词元时，卡片明确披露「这是词元 run 的读音」，以便不被 runs 冒充 run 的读音误导。
7. 作为英文学习者，我想要首次点词查详情后该词元自动记入生词本为学习中，以便查词本身就是「不会」的信号而无需额外操作。
8. 作为英文学习者，我想要在弹卡里把词元显式改为已掌握或已忽略，以便四态（New/Learning/Known/Ignored）由我完全掌控、系统永不凭猜测改状态。
9. 作为英文学习者，我想要学习中的词在阅读里保持查词底色、已掌握与已忽略的词弱化回普通文本，以便会的词从辅助里「消失」、注意力留给生词。
10. 作为英文学习者，我想要生词本状态跨词形、跨文档按词元通用，以便在 A 书标了已掌握的词在 B 书也认识。
11. 作为英文学习者，我想要扩展记住最近打开的文档和每个文档的阅读位置，以便重开扩展接着上次读。
12. 作为英文学习者，我想要断网状态下一切照常（标音、查词、改生词状态），以便飞机上、代理断了都能用。
13. 作为英文学习者，我想要点卡片上的发音按钮听到单词读音，以便音、形、义一次到位。
14. 作为英文学习者，我想要文本层完好的 PDF 也能在扩展阅读页打开阅读，以便同一入口处理两种格式。
15. 作为英文学习者，我想要扫描版 PDF、加密或损坏的文档得到明确的「不支持/已损坏」提示而不是白屏或崩溃，以便知道边界在哪。
16. 作为英文学习者，我想要打开大书时按章节渐进加载，以便整本书不一次性卡死界面。
17. 作为英文学习者，我想要扩展的生词数据按与服务端词架相同的四态词元语义组织，以便将来决定数据同源合并时不用推倒重来。
18. 作为英文学习者，我想要右键菜单里的「用 LinguaLeaf 打开」快捷入口，以便从下载完成的文件一步进入阅读。

## Implementation Decisions

- **架构**：遵循 ADR-0006——全链路浏览器内完成，任何时刻不存在 LinguaLeaf 服务进程。目标浏览器锁定 Edge（Chromium/MV3），加载解包分发，个人使用。
- **工程**：monorepo 新增 `@lingualeaf/extension` 包（Vite + TS，与 web 同构建体系），多入口：扩展阅读页、service worker（仅入口事件，不持状态）、manifest。生词存储与词架 schema 同构（四态按词元），类型共享自 `@lingualeaf/reading-model`。
- **离线词典**：构建期从服务端词典数据导出烘焙——词形→美式 IPA、词元映射表、高频词中译。裁剪规模在实现票内量测定（资产体积与覆盖率权衡），缺词一律留空。运行期由 `Dictionary` 接口的离线实现承载：词形优先，词元回退必须显式披露（卡片标注来源），不得冒充词形读音。
- **标注管线**：复用共享阅读模型的分词规则与音标行构建函数——槽位数组（每词一槽，缺词空串）是词-音标配对的唯一真相源，音标行渲染两端一致。扩展侧零改动复用。
- **导入链**：EPUB 导入复用服务端既有纯链（解包→HTML 抽取→句子切分→书模型）。认领票第一步验证该链的浏览器纯度（JSZip/DOMParser 皆浏览器原生）；若发现 Node 专属依赖，把纯链提取进共享包——只搬移不改行为，服务端改为从共享包引入。
- **存储 seam（唯一新 seam）**：定义与服务端注入形状一致的生词存储接口——含「查词即状态」语义（未记录的词元在同一次调用内进入 Learning，已有记录不动，返回落定后的状态；查不到不写任何东西）与阅读进度、最近文档列表。两个实现：内存 fake（测试）、chrome.storage 实现（真实）。阅读页 UI 不直接触碰 chrome.* API。
- **异步写不变量**：扩展内所有在途写沿用属主令牌语义（GLOSSARY）——切走、重入、作废的响应不落盘、不误报；弹卡 A→B→A 再入、同词形共享条目的语义与 web 端 characterization 钉子一致。
- **弹卡数据契约**：与 web 端点词查详情响应同构——词元、美音 IPA、词性、中译、生词本状态；New→Learning 的一次性自动迁移在存储实现内完成。资产中译缺失时卡片相应位置留空。
- **四态呈现**：Learning 词保持查词底色，Known/Ignored 弱化回普通文本（ADR-0005 视觉语义）；状态变化即时反映到当前渲染。
- **PDF**：原位词级标注以验证票前置——在缩放、多栏、断行样本上验证音标行不遮挡正文、词对齐正确、可开关；通过则 PDF 走与 EPUB 同一标注管线，不通过则 PDF 降级为提取重排视图（文本流），标注管线不变。扫描版 PDF 依「书」的词条定义明确提示不支持。
- **错误路径**：加密/DRM 文件、损坏档案、超大文件在导入时明确报错并保留可用状态；错误信息面向用户，不暴露内部细节。
- **零服务端行为变更**：本特性不改变服务端任何对外行为；仅允许为提纯导入链做等价搬移。

## Testing Decisions

- 好测试只断言外部行为：渲染出的音标行与槽位、卡片内容、状态迁移后的可见结果、错误提示——不测内部函数调用方式。
- **导入链**：确定性 fixture EPUB 过全链断言章节模型（先例：服务端导入测试；fixture 构建用 JSZip，注意 date 与隐式目录项的确定性——建目录显式化）。
- **标注管线 + 离线 Dictionary**：小型 fixture 词典资产过管线，断言槽位（词形命中、词元回退含披露、缺词留空）（先例：服务端 dict/音标行测试）。
- **阅读页 UI**：jsdom 组件测试——fixture 书 + 内存 store，deferred 断言在途写语义（先例：wordLookup 测试的 deferred PUT 模式与既有 characterization 钉子）。
- **存储实现**：内存 fake 承载全部行为测试；chrome.storage 实现保持薄（类型 + 原子读写），不单独铺测试面。
- 不引入 supertest/E2E 新面（扩展无服务端）；PDF 验证票含真浏览器人工验证步骤（判据见上）。
- 收官加一道独立 cc-suite 审核门：qwen-review 走查扩展整 diff，qwen 不可用时按 07 票降级条款转 Codex 审查，不得静默跳过。

## Out of Scope

- 服务端任何功能变更：数据同源合并、同步协议、导出生词（后者是同源合并的候选素材，另票）
- 译文行与 DeepSeek/联网兜底（离线词典中译仅用于弹卡；联网兜底是后置可选项）
- 导出注音副本文件
- txt、网页正文、docx；网页划词标注
- 扩展商店上架、系统文件关联（双击打开）
- 设置面板（字号、主题）、英式/美式切换（锁定美式）
- Firefox / Safari

## Further Notes

- Codex Top 3 风险的对应缓解：PDF 遮挡→验证票前置且可降级；词元冒充词形→强制披露规则入词典接口契约；双份数据无合并协议→schema 同构 + 同源另票。
- 本 spec 的代码事实断言（槽位真相源、存储注入形状、导入链构成）已对照当前代码核实；导入链浏览器纯度是唯一待验断言，已写成认领票义务。
- 阅读进度与最近文档列表存在扩展本地；卸载扩展即随浏览器存储一并消失。
