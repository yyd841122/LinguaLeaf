# 01: 服务端书签存储与 API(bookmarks 表 + 三路由 + 契约)

Status: done

**What to build:**

- `apps/server/src/schema.ts`:新表 `bookmarks`——id INTEGER PRIMARY KEY
  AUTOINCREMENT、book_id INTEGER NOT NULL REFERENCES books(id) ON DELETE
  CASCADE、chapter_position / block_position INTEGER NOT NULL、created_at
  TEXT NOT NULL(循 books.created_at 惯例)、UNIQUE(book_id, chapter_position,
  block_position)。走 CREATE TABLE IF NOT EXISTS 原地迁移路径,零表重建。
- `apps/server/scripts/check-sql-locality.mjs`:TABLE_OWNERS 登记
  bookmarks → book-store。
- `apps/server/src/book-store.ts`:listBookmarks(按 (chapter, block) 升序)/
  addBookmark/deleteBookmark。addBookmark 单事务:目标块存在性轻量查询
  (不复制 progress PUT 的整章加载)→ 上限检查(常量
  MAX_BOOKMARKS_PER_BOOK = 100)→ INSERT OR IGNORE 幂等去重,
  返回 created | existing(同块重试返回 existing,不受上限影响);
  deleteBookmark 按 (bookId, bookmarkId) 双限定——他书的 id 不得删。
- `apps/server/src/books-router.ts`:
  - GET /api/books/:id/bookmarks → 200 {bookmarks: [...]}(书就绪但无签
    = 空数组,不是 404);404 book-not-found / 409 book-not-ready。
  - POST /api/books/:id/bookmarks,体 {chapter, block}(正整数):
    201 {bookmark} 新建 / 200 {bookmark} 已存在 / 400 / 404 book-not-found /
    404 bookmark-target-not-found / 409 book-not-ready /
    409 bookmark-limit-reached;错误体沿用 code + error。
  - DELETE /api/books/:id/bookmarks/:bookmarkId → 204 幂等(书存在即 204,
    含已删与他书 id);404 book-not-found。
- `apps/server/src/wire.ts`:BookmarkSummary {id, chapter, block, createdAt}
  (camelCase 循 wire 既有)。
- `apps/web/src/bookmarks.ts`:三 helper(fetchBookmarks / createBookmark /
  deleteBookmark),口径对齐 readingProgress.ts——书不存在 404 与其他失败
  分开,失败不静默吞、不写状态。
- 测试:`apps/server/test/schema.test.ts`(旧库升级 + 重复启动幂等)、
  `book-store.test.ts`(去重 / 上限 / 级联删 / 事务原子)、
  `api.test.ts`(HTTP 错误矩阵逐码)、`contract.test.ts`(bookmarks.ts
  三 helper 解析形状)。
