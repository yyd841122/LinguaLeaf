# 译文按需分章生成，导入只生成音标

ADR-0002 把音标与译文都压在导入时生成，其自述代价——导入要等几分钟、为没读的部分白花
LLM 费用——恰是实践中最疼的两处。现拆开：音标本就是本地词典查询，零费用、秒级，维持
导入时生成；译文改为「按需翻译」（GLOSSARY.md）：阅读页工具栏按章手动触发，后台任务
带百分比进度，允许重翻覆盖，同一章翻译中再点返回 409，服务重启时残留 translating 的
章清扫为 failed。阅读与导出对缺译文的容错路径（空占位行/省略译文行）早已存在并被测试
钉住，故不设"先翻译才能导出"的门槛；未配置翻译服务时按钮置灰加提示。0002 否决的是
"阅读时自动实时生成"——按需翻译是手动触发的预生成，译完的章阅读路径依旧零外部依赖，
0002 的理由对音标与译完的章仍然成立，生成时机这一半由本决策取代。

## Considered Options

- 维持导入时全量预生成（ADR-0002）：导入慢、为未读部分付费，被日常使用否决
- 阅读时按页自动实时生成：ADR-0002 已否决——每翻新页都要等、依赖网络稳定
- 「翻译全书」一键：成本与导入全量相同，只是把等待换个位置，未选
- 按章手动触发（选定）：钱只花在读过的章，任务粒度与既有 translateChapters 天然对齐
