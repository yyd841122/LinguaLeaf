# 浏览器扩展采用彻底无服务的本地标注架构

「打开英文文档即标音标」的诉求落为**浏览器扩展（GLOSSARY.md）**：扩展阅读页打开
PDF/EPUB，标注（音标行）由**离线词典**在浏览器内完成，全链路不存在 LinguaLeaf
服务进程——不手动启动、不后台常驻、也不按需无感拉起。目标浏览器锁定 Edge
（Chromium/MV3），个人使用，加载解包扩展分发。
既有资产复用纯 TS 部分：`@lingualeaf/reading-model` 模型、音标行渲染
（ipa-line）、美式 IPA 词典数据构建期烘焙为扩展资产；Node/better-sqlite3
服务端代码不进浏览器。词形查不到音标回退词元时须显式披露，不得冒充词形读音。
代价：生词数据与词架（SQLite）形成两份本地数据。扩展侧按 ADR-0005 四态词元
语义自管存储，与词架的同源合并留作后续独立决策，本 ADR 不预先绑定方案。
范围：EPUB 先行；PDF 原位标注取决于词级坐标验证（现 import 管线只保留段落
文本），验证不过则 PDF 降级为提取重排视图；txt/网页/docx 不在本期。

## Considered Options

- 服务后台常驻（开机自启/systemd）：消灭手动启动但引入常驻进程，违背「任何时刻无服务」的意图
- 按需无感拉起（原生宿主）：OS 层一次性安装宿主，仍有服务进程，与上者一并否决
- 扩展直连 DeepSeek / 免费 API：key 无法按服务端秘密保护、离线不可用、延迟与配额不可控——至多作后置可选兜底，不作架构
- 浏览器内本地标注（选定）：无进程、无 key、离线可用；代价是数据分叉与词典资产体积
