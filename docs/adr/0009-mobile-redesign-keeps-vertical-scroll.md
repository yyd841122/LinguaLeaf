# 手机端 UI 改版保持竖向连续滚动,不引入分页翻页

2026-11-16 拍板的手机端 UI 改版(暖纸沉浸阅读页 + 微信读书式骨架,`.scratch/mobile-ui-redesign/`)取微信读书的交互范式——菜单默认隐藏、点按呼出、边缘点按翻页——但**不**随之引入它的分页翻页模型:正文维持扩展阅读器一脉相承的竖向连续滚动。左右点按热区落在 22% 宽页边距上,翻的是**章**(前一章 / 后一章),不是页。**(2026-11-16 评审修订:翻章约束限定 EPUB 与 Markdown;PDF 例外——原版与重排视图的边缘点按仍按 PDF 物理页导航。两套导航契约并存是有意为之:页本就是 PDF 的自然阅读单元,EPUB 的自然单元是章。)**

## Considered Options

- 分页翻页(微信读书同款:左右滑动 / 点按按屏翻页,仿真或平移动画):句子块的 kernel 组件(`AnnotatedBlockView`)以 `line-height: 2` 预留标注带、逐词对齐音标,按屏重排意味着在四个宿主(web / 扩展 / 导出 / 手机)共享、浏览器实证过的 kernel 最贵处重写一套分页引擎,每一屏都要重算标注带布局
- 双模式并存(滚动 + 分页可切):两套导航心智 + 分页引擎照付,维护面翻倍;个人自用没有撑起这份复杂度的需求
- 竖向滚动 + 点按翻章(选定):导航语义降一级到章;滚动位置即阅读进度(阅读进度 store 已承接);kernel 零改动,改版成本全部落在观感与外围

## Consequences

- 「翻页」语义在手机端 = 翻章(EPUB / MD)、翻物理页(PDF 原版与重排);页内 / 全书尺度的移动走目录面板的进度滑杆(EPUB 章节进度 / PDF 页)
- 分页与翻页动画类需求(仿真翻页等)不在此形态内;真要分页须新 ADR 取代本条,预计届时仍绕不开动 kernel
- 22% 宽边距(参照图风格载体)与边缘热区互相成全:空边距天然是热区,不与点词查详情冲突
